# Jev 広告クリーナー PoC

Chrome Manifest V3拡張。**手動実行、またはすべてのサイトで常時オン**で表示済みページの広告候補を抽出し、選択した接続先（Cloudflare AI Gateway／TypeSafe API直接接続）のJevが広告と判定した要素をDOMから除去します。削除閾値は初期値90%。直前／全件復元に対応します。

初期設定は手動実行です。「すべてのサイトで常時オン」を有効にすると、現在のページ、次回アクセス、再読み込み、別サイトへの移動で自動判定・削除します。遅れて追加される広告も上限内で判定します。Cloudflare Gateway／TypeSafe直接接続を選択できる拡張機能です。

## 起動

事前に `npm ci && npm run build` を実行して `dist/` を生成してください。

1. Chromeの `chrome://extensions` でデベロッパーモードをON。
2. 「パッケージ化されていない拡張機能を読み込む」で、このディレクトリの `dist` を選択。
3. 拡張機能の「APIキー・サイト設定」で接続先を選択。
   - **Cloudflare AI Gateway**：Account ID、Gateway ID、Workers AI / Read権限を持つCloudflare APIトークンを入力。GatewayのUnified Billingにクレジットを用意。
   - **TypeSafe API（直接接続）**：TypeSafe APIキーのみ入力。Cloudflare設定は不要。
4. 外部送信・料金の説明を確認して保存し、「接続テスト」を実行。接続先を変更するとキー入力欄はクリアされ、新しいキーの保存後に切り替わります。保存前の選択変更だけでは実行先は変わりません。
5. `https://iphone-mania.jp/` 等を開き、拡張機能の **このページを判定・広告を削除** を押す。初回はChromeのサイトアクセス許可が必要。
6. 「直前を復元」「すべて復元」で戻す。常時オンがOFFの場合、後から表示された広告にはもう一度実行する。

常時オンがOFFのとき「再スキャンの動作モード」を診断にすると、下の再スキャンボタンでは削除せずに判定を確認できます。上の主ボタンは常に削除モードで実行します。復元した要素は同じページ内では再削除しません。リロードするとリセットします。

APIキー／トークンは拡張機能の `storage.session`（信頼された拡張機能コンテキストのみ）に保持します。ブラウザ終了／拡張機能再読み込み後は再入力してください。選択した接続先、Account IDとGateway ID、サイト設定はローカルに保存します。トークンはコード・ZIP・同期ストレージ・ページには含めません。個人用PoCであり、共有トークンを配布する構成ではありません。

## 通信

```text
ポップアップのボタン
  または全サイト常時オンのときに読み込み・ページ遷移・広告追加
  → 対象タブのDOMから広告候補を抽出（最大50件／実行）
  → Service Worker（最大10件／バッチ）
  → POST https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/run
      Authorization: Bearer {Cloudflare API token}
      cf-aig-gateway-id: {gateway_id}
      { model: "typesafe/jev", input: { state, questions } }
  → Noul広告確率を検証
  → 同じページ・同じ要素であることを再確認して削除
```

TypeSafe直接接続では `POST https://api.typesafe.ai/v1/systemone` に `{ model: "jev-latest", state, questions }` を送ります。Cloudflare用ヘッダーは付けません。接続先ごとのキーを自動流用することや、失敗時の別接続先への自動切り替えはしません。既存の0.2.0設定はCloudflareとして引き継ぎます。

候補の最大500文字のテキスト、広告ラベル、要素種別・寸法、広告属性の有無、リンク／iframeのホストを選択した接続先経由でTypeSafeへ送ります。ページ全文、フォーム値、完全URLやクエリは送りません。候補テキスト自体に個人情報が含まれる可能性はあります。Cloudflare接続時のGatewayログ収集・キャッシュは要求単位で無効にしています。実APIテストには利用料金がかかります。

公式仕様: [TypeSafe直接API](https://docs.typesafe.ai/introduction/quickstart) / [Jev](https://developers.cloudflare.com/ai/models/typesafe/jev/) / [Cloudflare AI Gateway REST API](https://developers.cloudflare.com/ai-gateway/usage/rest-api/)

## 検証コマンド

```sh
npm ci
npm run build
npm test
npm run test:e2e
npm run test:site
```

PlaywrightのChromiumが必要です。未導入の場合は `npx playwright install chromium`。テストは別プロファイルのChromiumに実拡張機能を読み込みます。`test:e2e` は合成ページ、`test:site` は公開中のiPhone Maniaを使用します。**両方ともAI通信は明示的なモック**です。実Jevの広告判定精度・Cloudflare認証成功は検証しません。

テスト用の拡張コピーだけに対象ホスト権限を追加し、ポップアップを拡張タブに表示してactive-tab取得を差し替えます。Chromeのネイティブ許可ダイアログ・ツールバーの開閉は自動検証外です。スクリーンショットと実サイトの検証結果JSONはOS一時フォルダーに保存します。

## 制限

- ネットワーク広告ブロックではなく、表示後のDOM除去です。通信・追跡・動画広告は止めません。
- 全要素をAIに送る方式ではありません。広告属性、ラベル、広告ネットワークなどの手掛かりを持つ候補だけを送るので、手掛かりのない広告は見逃します。
- Shadow DOM内部・クロスオリジンiframe内部は判定しません。iframe外側は候補になり得ます。
- 記事やフォームを含む要素、画面面積の40%を超える大きな要素は保護します。
- 1回50候補、1時間300要求、同時2要求、10秒タイムアウト。セッション上限は厳密な課金上限ではありません。
- API失敗・不正な確率・ページや要素の変化時は削除しません。判定途中の再操作は完了を待ってから行ってください。
- 復元用に最大5000 DOMノードを保持します。元の親要素が消えた場合やSPA遷移後は復元できない場合があります。
- 閾値90%はユーザー指定の値です。実モデルの精度は接続情報を設定した後に確認する必要があります。

## 常時オン

拡張機能ポップアップの「すべてのサイトで常時オン」で切り替えます。有効化時に現在のページも判定します。設定は拡張機能全体で保存し、新しく開くHTTP/HTTPSサイトでも個別のON操作なしで自動実行します。Chrome内部ページなど拡張機能が動けないページは対象外です。サイトごとの削除閾値は引き継ぎます。常時オンでは削除モードに固定します。OFFにすると未完了の判定を無効化して手動実行へ戻り、すでに削除した要素は「復元」で戻せます。

自動判定は1ページ50候補までで、再読み込み・ページ遷移でリセットします。手動再スキャンでもリセットします。1時間300要求の共通上限は継続します。APIエラー後の自動送信は停止し、再読み込みか手動再スキャンで再開します。

常時オン設定は再起動後も保持しますが、APIキーはセッション保存のためブラウザ再起動後に再入力が必要です。キー未設定の間は自動判定しません。APIキー保存後、開いている対象ページでも再開します。復元した広告は同じページ内で再削除しません。

## 広告iframeの判定改善

iframeのAdvertisementラベル、Google広告iframe形式、第三者広告タイトルを候補情報に追加しました。生の広告IDは送信しません。閾値未満で保持した場合は理由をポップアップに表示します。2026-09-23の実Chrome・TypeSafe直接APIで、小説家になろうの広告判定は情報追加後84〜89%でした。この利用環境の同サイトのみ閾値を80%に調整し、遅延表示枠の再スキャンを含め4枠の削除を確認しました。この検証時点では他サイトの初期閾値は95%でした（現在は全サイト90%）。閾値80%は当該ページでの確認に基づく暫定設定で、一般的な精度を保証する値ではありません。

0.5.0検証: 単体テスト20件、ブラウザ検証17項目成功。外部APIを模擬したテストで、設定のない新しいドメインの自動削除・再読み込み・OFF時の未完了結果の無効化を確認。

0.5.1: ユーザー指定で新規サイトの削除閾値を90%に変更。初回更新時に既存サイトの閾値も90%へ移行。

0.5.2: ポップアップと設定画面の常時オンは同じ設定であることを明記し、開いている両画面のチェック状態を同期。サイト別設定が空でも全サイトの自動実行状態を明示。同期時に入力中の接続設定・キー・閾値は保持します。
